# База данных

Каждый изучаемый язык живёт в своём разделе базы (schema) с кодом языка: `hy`, `uz`, … Раздел содержит
всё приложение этого языка: словарь, курсы, прогресс, подписки, админку.

Миграции применяет `scripts/migrate.py` (workflow «Deploy Supabase»). Для каждого языка из `langs.json`:

| Папка | Что | К каким языкам |
|---|---|---|
| `base/<base>/` | исходная цепочка миграций приложения-образца (`base` в langs.json) | ко всем языкам с этой основой |
| `lang/<код>/` | изменения только для одного языка | к этому языку |
| `common/` | изменения движка для всех языков | ко всем |

Файлы пишутся как для раздела `public` (`public.words`, `schema public`) — при применении `public.` заменяется
на раздел языка (`hy.words`). Роль `public` в `revoke … from public, anon` не меняется.
Учёт применённых — таблица `supabase_migrations.schema_migrations`, версия `<код>:<имя файла>`.
Файлы применяются по алфавиту имён внутри языка; уже применённый файл больше не меняют — правка = новый файл.
